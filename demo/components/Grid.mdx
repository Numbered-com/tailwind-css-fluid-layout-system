## How it works

Each breakpoint writes four variables on `html`: `--column`, `--gutter`, `--margin` and `--grid-width`. They are expressed in `vw`, so a 1440px mockup renders pixel perfect at 1440px and keeps its proportions at every other width. The faint lines on this page are the grid guidelines.

## Fluid type

The root font size follows the same rule: `1rem` equals 16px at the mockup width and scales with it. Every rem based Tailwind value (font sizes, spacing, radii) scales in step with the grid, so type set in the mockup keeps its size relative to the layout. Set `fontScalingMaxWidth` to stop the growth on large screens; the simulator above marks where it kicks in.

## Columns

`span-*` sizes an element to a number of columns, gutters between them included.

<div className="flex flex-col">
	<div className="tile span-w-1">span-w-1</div>
	<div className="tile span-w-2">span-w-2</div>
	<div className="tile span-w-3">span-w-3</div>
</div>

Add `-wide` for one extra gutter, `-wider` for two. Handy for offsets that land on the next column.

<div className="flex flex-col">
	<div className="tile span-w-2">span-w-2</div>
	<div className="tile span-w-2-wide">span-w-2-wide</div>
	<div className="tile span-w-2-wider">span-w-2-wider</div>
</div>

## Gutters and margins

`gutter-*` and `margin-*` give multiples of the gutter and of the outer page margin.

<div className="flex gutter-gap-1">
	<div className="tile span-w-2">span-w-2</div>
	<div className="tile span-w-2">gutter-gap-1</div>
	<div className="tile span-w-3">span-w-3</div>
</div>

<div className="flex">
	<div className="tile span-w-2">span-w-2</div>
	<div className="tile span-w-2 gutter-ml-1">gutter-ml-1</div>
	<div className="tile span-w-2 span-ml-1-wider">span-ml-1-wider</div>
</div>

## Any property

The three prefixes combine with width, height, padding, margin, inset, gap, scroll spacing, border width and text indent. Negative values and arbitrary counts work too: `-span-ml-1`, `span-w-[1.5]`, `span-w-[1.5_wide]`.

## Nesting

CSS grid tracks stop at component boundaries, and subgrid only reaches one level down. These utilities resolve to viewport units, not percentages of the parent, so `span-w-2` has the same width in the body, in a flex row, in a grid cell or in an absolutely positioned box four wrappers deep. Offset each level by whole columns and its content stays on the page grid, whatever the parent is.

<section className="nest w-fit span-pl-1-wide gutter-pr-1 lg:span-pr-1-wide" data-node="section · static">
	<div className="nest relative flex span-pl-1-wide gutter-pr-1 lg:span-pr-1-wide" data-node="div · relative flex">
		<article className="nest grid span-pl-1-wide gutter-pr-1" data-node="article · grid">
			<div className="tile span-w-2">span-w-2</div>
		</article>
	</div>
</section>

## From mockup to class

The bundled CLI converts a measured pixel width into the closest class.

```bash
bunx px-to-cols 330 --columns 24 --mockup 1440 --gutter 24 --margin 24
# → span-w-6 (330px, exact)
```
